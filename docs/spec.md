# word-loop MVP仕様

## 目的
20語だけで、実際に日常利用できる英単語高速周回Webアプリを完成させる。
まずは自分で使える品質まで仕上げ、その後に公開を検討する。

## 技術方針
- React + TypeScript + Vite
- Windowsで開発し、iPhoneのブラウザでも利用できるWebアプリにする
- 安定版の新しい技術を優先し、不要な実験機能は使わない
- サーバーやアカウント機能はMVPでは持たない
- 単語データと表示・再生処理は分離する

## MVP必須機能

### 1. 単語
最初は20語のみ。
難しい単語は避け、絵にしやすく意味が分かりやすい基本語を使う。

初期候補:
apple, dog, cat, water, sun, book, car, tree, house, hand,
bird, fish, flower, moon, chair, shoe, cup, door, bread, rain

単語データはコードへ直接埋め込まず、JSON等の独立データとして管理する。

### 2. 表示
画面はシンプルにする。

主表示:
- 絵
- 大きな英単語
- 日本語訳

補助表示:
- 3語程度の短い英文・語句
- 補助表示はON/OFF可能にする

不要な説明文や細かいラベルを画面中央に増やさない。

### 3. 自動周回
単語を自動的に次へ送る。

速度:
- 0.2秒/語 ～ 3.0秒/語で調整可能
- 高速周回を重視する

プリセット候補:
- 超高速: 0.25秒/語
- 高速: 0.5秒/語
- 標準: 1.0秒/語
- ゆっくり: 2.0秒/語

### 4. 音声
英単語の発音を再生できるようにする。

2つの動作を分ける:
- 音声終了待ち: 読み上げ終了後に次へ進む
- 高速周回: 音声終了を待たず、設定速度で次へ進む

MVPでは、著作権・利用規約・秘密情報・追加課金の問題が少ない方法を優先する。
外部の教材音声を無断利用しない。

### 5. 絵
各単語に対応する絵を表示する。

条件:
- 著作権・利用規約上、将来公開可能な素材のみ使う
- 外部サイト画像の無断転載やホットリンクはしない
- 自作、生成、または再利用条件を明確に確認できる素材を使う
- 素材の出所や条件が不明な場合は採用しない

### 6. 保存
ブラウザ内に最低限の状態を保存する。

保存対象:
- 最後に表示していた単語
- 速度設定
- 音声ON/OFF
- 補助英文ON/OFF

MVPではログインやクラウド同期は行わない。

## UI方針
- iPhoneで片手でも扱いやすいこと
- 主役は英単語と絵
- 操作部品を増やしすぎない
- 高速周回中でも見づらくならないこと
- タップ領域は小さくしすぎない

## セキュリティ・公開方針
- APIキーや秘密情報をブラウザコードへ埋め込まない
- 個人情報を扱わない
- 不要な外部通信を増やさない
- 新規外部サービス、課金、権限拡大、データ送信は導入前に確認する
- 非公開開発中でも、将来公開できない素材を混ぜない

## MVPでは行わないこと
現時点では以下を必須にしない。

- ユーザー登録
- クラウド同期
- App Store向けネイティブ化
- CSV取込
- 大量の単語データ
- バックグラウンド再生
- 複雑な学習履歴・成績管理
- 外部画像検索API
- 外部AI API

## 開発の進め方
- 仕様・意思決定はWeb版ChatGPTで行う
- 確定事項はGitHubへ保存する
- ローカルCodexはGitHubをpullし、AGENTS.mdと本仕様を読んで実装する
- Claude Codeへ交代する場合も同じルールと仕様を参照する
- まず動く最小版を作り、実際に使ってから機能追加を判断する
