# Task 021: 通常の遠征を Kokoro 音声へ切り替える

## 目的
試聴の結果、Kokoro の音質を採用する。通常の遠征でも、Task 020 で生成した音声を再生する。
学習テンポ（設定秒数での自動送り）と保存データは変えない。

**音質の採用は、全項目の発音確認が終わったことを意味しない。** Task 020 の要判断17項目・要確認15項目と、
「自動検査済み・未試聴」の記録（`src/data/vocabularyAudio/pronunciations.json`、`reviews.json`、試聴画面の状態表示）はそのまま残している。

## 方針の変更（古い仕様より優先する）
- `docs/spec.md` の「4. 音声」は「音声終了待ち」と「高速周回」の2つの動作を挙げていたが、今回は **高速周回だけ** とする（音声終了待ちは作らない）。
  設定秒数で次へ進み、音声が終わっていなければ途中で止めて、次の語を先頭から再生する。
- Task 002 以降の「通常の遠征はブラウザ標準の音声合成（Web Speech API）で読み上げる」を改め、遠征では speechSynthesis を使わない。
  Web Speech API は試聴画面の「現在の読み上げ」（聴き比べ）にだけ残す。
- `docs/spec.md` と `README.md` の音声の説明を更新した。

## 仕様

### 音声の選択
- 表示中の語の wordId で、Task 020 の音声 `public/audio/kokoro-vocabulary/{wordId}.mp3` を再生する。
- 対応は、生成スクリプトが書き出す軽い一覧 `src/data/vocabularyAudio/audio-index.json`（wordId → 音声の SHA-256 の先頭8文字、約42KB）で引く。
  - 詳細な検査情報を含む `manifest.json`（847KB）は遠征では読み込まない。
  - URL にハッシュを付け（`?v=…`）、音声を作り直したときにブラウザのキャッシュから古い音声を再生しないようにした。
- 要判断17項目は、Task 020 で補助文の意味に合わせて仮に選んだ主の音声（`{wordId}.mp3`）を使う。比較用の別の読み（`{wordId}.{key}.mp3`）は遠征では使わない。
- 語彙・訳・品詞の分割・発音の再判定は行っていない。

### 再生のタイミング
| 操作 | 音声 |
| --- | --- |
| 遠征開始（最初の語） | 音声 ON なら再生 |
| 自動送り・「次へ」・「前へ」でカードが変わる | 音声 ON なら前の音声を止め、新しい語を先頭から再生 |
| 設定の「発音を再生」 | 表示中の語を先頭から再生（連打しても毎回先頭から。自動周回の停止中も使える） |
| 再生できなかった表示（後述）を押す | 表示中の語を再生し直す |
| 自動周回を停止 | 今の音声を止める |
| 自動周回を再開 | 何も再生しない。表示中の語を設定秒数だけ見せてから次へ進む（二重に始めない） |
| ×／✓ | 何もしない（音声を再生し直さない。回答・猫の動作も従来どおり） |
| 音声 OFF | 今の音声を止め、以後カードが変わっても読み込まない |
| 遠征完了・帰還・拠点へ戻る | 音声を止める |
| 画面を離れる（タブ・アプリの切り替え、ページを閉じる、試聴画面へ移る） | 音声を止める。非表示の間は、自動送りでカードが変わっても新しい音声を再生しない（下記「レビュー指摘の修正」） |
| 非表示から表示に戻る | 何も再生しない（非表示の間に見送った音声を後からまとめて再生しない）。次のカードの切り替え・「発音を再生」から通常どおり再生する |

- 自動送りのタイマーは従来どおり（音声の長さ・読み込み・失敗に関係なく設定秒数で進む）。0.25秒/語などの高速周回では音声が途中で切れる。
- 音声要素は1つだけを使い回すので、音声が重なることはない。
  - 次の語に移ると読み込みを打ち切り、前の語の遅れた読み込み完了・再生開始・失敗は通し番号で無視する。
  - 同じ要素を使い回すのは、iPhone Safari では、ユーザー操作（「遠征を始める」など）で一度再生した要素なら、その後タイマーからも再生できるため。
- 全1,489項目の MP3 は起動時に読み込まない。読み込むのは再生する語の MP3 だけ（先読みはしない）。出題順は変えていない。

### 再生できない場合
| 理由 | 判定 | 表示 | 押すと |
| --- | --- | --- | --- |
| 音声がない（一覧にない） | 一覧に wordId がない（通信しない） | 「音声なし」 | ―（押せない） |
| 読み込み失敗（404・通信失敗・形式エラー） | 音声要素の `error`、`play()` の失敗 | 「音声エラー」 | 再試行 |
| ブラウザが自動再生を拒否 | `play()` が `NotAllowedError` | 「▶ 音声」 | 表示中の語を再生 |

- 表示は画像枠の右上（枠の内側）に小さく重ねる。絶対配置なので、英語・訳・画像・補助文の位置は動かない（390×844・320×568 で英語の位置が変わらないことを確認）。
- 失敗しても遠征・自動送りのタイマーは止めない。ブラウザの読み上げへは切り替えない。
- 表示は次に再生できた時点で消える。音声 OFF の間は出さず、次の遠征の開始時にも消す。

### 保存
- 既存の音声 ON/OFF（`word-loop.learning-state` の `speechEnabled`）をそのまま使う。
- localStorage のキー・version・既存データは変更していない。音声の失敗状態は保存しない。
- 学習履歴・回答・出題期日・XP・Gold・猫の処理は変更していない（×／✓ の処理・猫・タイマーのコードに手を入れていない）。

### ブラウザ確認（Chromium・Playwright、`vite preview --port 5188`）
390×844 と 320×568 で、以下をすべて確認した（各35項目。レビュー指摘の修正後に全項目を再実行）。
- 自動再生の許可フラグは付けず、通常の Chromium と同じ条件（ユーザー操作の後なら再生できる）で実行した。
- 「古い語の再生」は、再生が始まった時点（`playing`）の音声の wordId と、表示中の英語を照合して数えた。

- 起動時に MP3 を読み込まない（0件）。遠征開始で最初の語を再生する。
- 次へ8回・前へ3回の連続操作: 最後に鳴ったのは表示中の語。古い語の再生 0、重なり 0、音声要素は1つ。
- 「発音を再生」を5回連打: 5回とも表示中の語を先頭から再生。
- 2秒周回（約6秒）: 3語進み、各語の音声が1回ずつ鳴った。古い語の再生・重なりなし。自動周回を開始した直後に二重の再生なし。
- 停止: 音声が止まり、語も進まない。停止中も「発音を再生」で再生できる。
- ×／✓: 音声を再生し直さず、表示中の語に記録される。
- 0.25秒周回（4秒）: 16語進み、play 16回。古い語の再生・重なりなし。停止で無音。
- 遅い通信（全 MP3 を1.2秒遅延）＋0.25秒周回: 古い語の再生 0。停止中の手動再生は表示中の語。
- 404: 「音声エラー」を表示し、英語の位置は変わらない。自動周回は止まらない（約1秒で5語進む）。表示を押して再試行し、再生できたら表示が消えた。
- 自動再生の拒否（`play()` が `NotAllowedError` を返す状態を、テスト用の差し替えで再現）:
  - 「▶ 音声」を表示し、遠征は続く。
  - 押すと表示中の語を再生し、表示が消えた。
- 音声 OFF:

  - 設定は `learning-state.speechEnabled` に保存される。ON に戻すと次の語から再生する。
- タブの非表示（`visibilitychange`）: 下記「レビュー指摘の修正」を参照。
- 0.25秒周回で105語まで進めて遠征完了: 音声は止まり、その後は再生しない。古い語の再生・重なりなし。
- localStorage のキーは従来の4つだけ（learning-progress v2・learning-state・player-progress v1・understanding v2）。新しいキーなし。
- 試聴画面へ移ると遠征の音声は止まる。試聴画面の「現在の読み上げ」ボタンは残っている。

## レビュー指摘の修正（2026-10-25）

### 指摘
自動周回・音声 ON のままページを非表示にすると、`visibilitychange` で今の音声は止まる。
しかし次の自動送りで `changeWord` → `speak` が呼ばれ、非表示のまま音声が再開していた。

### 修正
- 再生管理（`createWordAudioPlayer`）に `canPlay` を追加した。遠征では `document.visibilityState !== 'hidden'` を渡す。
- `canPlay` が false の間は、`play()` を呼ばれても読み込み・再生をしない。前の音声も止め、`suppressed` を通知するだけにする。
  見送った音声を覚えておいて、表示に戻ったときにまとめて再生することはしない。
- 表示に戻っても何も再生しない。その時点で表示中のカードは、次のカードの切り替え（自動送り・前へ／次へ）か「発音を再生」から通常どおり再生する。
- 出題・周回は変えていない。非表示の間もタイマーは従来どおり動き、出題も進む（ブラウザによるタイマーの間引きも従来どおり）。

### 回帰確認
- 単体テスト（`tests/wordAudio.test.ts`）:
  - 非表示の間に3回 `play()` しても再生・読み込みしない。前の音声は止まり、遅れて届いた前の再生のイベントも無視する。
  - 表示に戻っただけでは再生しない。次の `play()` から通常どおり再生する。
- ブラウザ（Chromium、390×844・320×568。`document.visibilityState` を `hidden` にして `visibilitychange` を送って再現）。0.5秒周回・音声 ON で確認した。
  - 非表示にした直後に音声が止まる。
  - **非表示のまま自動送りが6回進んでも**、再生 0回・MP3 の読み込み 0件で無音のまま。カードは進む。
  - 表示に戻った瞬間は何も再生しない。
  - その後は次の自動送りの語から再生し、戻ったときに表示していた語は鳴らさない。鳴り始めた時点の語はすべて表示中の語だった。
  - 戻った後の「発音を再生」は表示中の語を再生する。
- 実際のタブ切り替え・iPhone でのアプリ切り替え・画面ロックでの挙動は未確認（Chromium では状態を差し替えて再現した）。
