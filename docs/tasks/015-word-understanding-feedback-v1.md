# Task 015: 単語ごとの理解度を記録するボタン v1

## 目的
ユーザーが単語ごとに「わかる」「まだわからない」を任意で記録できるようにする。
今回は表示と保存まで。出現頻度への反映は次のタスクで検討する。

土台は PR #8（Task 013 のカード表示修正、Task 014 の Recall 無効化）の最新状態（940b2fe）。

## 仕様
1. 遠征中のカード下部に「わかる」「まだわからない」の2つのボタンを置く。
2. 入力は任意。押さなくても自動周回は止まらない。未回答を「まだわからない」とは扱わない。
3. 単語ごとに、未回答・わかる・まだわからないの3状態を持つ。未回答は記録がない状態。
4. 選択と最終回答日時を保存する。再回答したら最新の選択と日時で上書きする。
5. 同じ単語が再登場したら、前回の選択を控えめに表示する（選択中のボタンを強調する）。
6. 「わかる」は本人の自己申告で、習得や正解の判定ではない。
7. ボタン操作で次の語へ進めたり、自動周回を止めたり延長したりしない。
8. 高速周回で押している間に語が変わっても、押し始めた時点の語に記録する。タッチ・マウス・キーボードのどれでも、別の語に誤って記録しない。
9. ボタン操作を、カードタップの Attention（「もう一度」）として扱わない。

今回やらないこと: 自己申告による出現頻度や 9:1 の比率の変更、Attention・debt・XP・Gold の変更、習得判定、クイズ、Recall の再導入、
画像・語彙の追加、大規模なリファクタリング、新しいライブラリ、外部 API。

## 実装

### 保存処理（`src/lib/understanding.ts`、新規）
- `recordUnderstanding(map, wordId, status, answeredAt)`: 回答を記録する。再回答は上書き。元のデータは変更しない。
- `getUnderstanding(map, wordId)`: 記録がなければ `null`（未回答）を返す。
- `startUnderstandingPress` / `handleUnderstandingKeyDown`: 押し始めの語を覚える。キーの自動リピートを処理する（下記「誤記録の防止」）。
- `resolveUnderstandingTarget(press, answeredAt, currentWordId)`: 記録先の語を決める（下記「誤記録の防止」）。
- `parseUnderstanding` / `loadUnderstanding` / `saveUnderstanding`: 保存データの読み書き。
- new / growth / familiar の判定、選出、報酬からは参照しない（今回は表示と保存だけ）。

### 保存形式
- キー: `word-loop.understanding`（新規。既存の3つのキーとは別にする）
- 形式（version 1）:
  ```json
  {
    "version": 1,
    "words": {
      "apple": { "status": "known", "answeredAt": "2026-10-24T13:43:14.662Z" },
      "reluctant": { "status": "unknown", "answeredAt": "2026-10-24T13:43:15.020Z" }
    }
  }
  ```
  - `status`: `"known"`（わかる）または `"unknown"`（まだわからない）
  - `answeredAt`: 最後に回答した日時（ISO 8601）
  - 未回答の語は `words` に含めない
- 書き込むのはボタンで回答したときだけ。一度も回答しなければ、このキーは作られない。
- **旧データの読み込み**: このキーがない（Task 014 以前の）データは、全語を未回答として扱う。既存のキーは読み方も中身も変えていない。
  - `word-loop.learning-progress`（version 2）、`word-loop.learning-state`、`word-loop.player-progress`（version 1）
- **不正なデータ**: 語ごとに `status` と `answeredAt` を確認し、形式が違う語の記録だけを捨てる。JSON として読めない場合や形がまったく違う場合は、全語未回答として扱う。
  どの場合も、自己申告のキー以外（学習履歴・設定・XP・Gold）には触れない。読めなかった古い値は、次に回答したときに新しい内容で上書きされる。

### カードの表示（`src/App.tsx`、`src/App.css`）
- カードの行の並びは「ラベル → 英語 → 日本語 → 画像 → 補助文 → ヒント → 理解度ボタン」。英語から補助文までは Task 014 と同じ。
- ボタンは2列、高さ44px（片手で押せる大きさ）。文字は小さめの灰色で、英単語より目立たせない。
- 選択中（前回の選択を含む）のボタンは、太い枠線、チェック（✓）、太字、背景で区別する（色だけに頼らない）。`aria-pressed` も付ける。
- 「✓ まだわからない」も 320px 幅で1行に収まるようにし、ボタンの高さは選択の有無で変えない。英語・画像の位置は、未回答・わかる・まだわからないで変わらない。
- ボタンはカード全体の「もう一度」ボタンより手前（`z-index: 2`）に置いた。押しても Attention にはならない。
- 正誤の演出、通知ダイアログ、回答の要求は入れていない。アニメーションもないので、reduced-motion でも見た目は同じ。
- これまでカード下端に重ねて出していた「◯◯ をもう一度出します」は、ボタンと重ならないように「タップでもう一度」と同じ行に出すようにした（文言・色・表示時間は従来どおり）。

### 誤記録の防止
- ボタンを押し始めたとき（`pointerdown`、キーボードの Enter / Space の `keydown`）に、その時点で表示中の語を覚えておく。
- 確定したとき（`click`）は、覚えておいた語に記録する。Space のように離したときに確定する操作で、その間に表示が変わっても、押し始めた語に記録される。
- 押し始めの情報がない操作（支援技術からの実行など）や、10秒より古い押し始めの情報（押しかけて指を外した場合など）は使わず、確定した時点で表示中の語に記録する。
- 押下の時刻はイベントの `timeStamp` で比べる。
- **キーの自動リピート**（レビューで発見し、修正済み）: Enter / Space を押し続けると、OS の自動リピートで `repeat: true` の keydown が繰り返し届く。
  - 修正前は、この keydown でも押し始めの語を上書きしていた。そのため Space は、離したときに表示中の語へ記録されていた。
  - Enter はリピートのたびに click が起き、表示が変わるたびに別の語へ連続で回答していた。
  - 修正後は、`repeat: true` の keydown では押し始めの語を上書きしない。Enter は自動リピートの既定の動作を止める（`preventDefault`）ので、連続の click も起きない。
  - Space は離したときに1回だけ click が起きるので、リピートは無視するだけにした。キーを離してから押し直す通常の再押下は、従来どおりそのとき表示中の語に記録する。

## テスト（`npm test`、89件）
既存77件はすべて維持し、`tests/understanding.test.ts` に12件を追加した（キーの自動リピートの修正で5件を追加）。

- 記録のない語は未回答（`null`）で、「まだわからない」とは扱わない
- 両方のボタンの状態を対象の語に記録でき、再回答は最新の選択と日時で上書きされる（ほかの語・元のデータは変わらない）
- 押下中に表示が変わっても押し始めた語に記録される。押し始めの情報がない・古すぎる・時刻が逆転している場合は、表示中の語に記録される
- version 1 の形式で保存でき、読み込むと同じ内容に戻る
- 自己申告のキーがない旧データでは、全語が未回答になる
- 形式が違う語の記録だけを捨て、ほかの語の記録は残す
- 壊れた自己申告データ（JSON として読めない、`null`、配列、文字列、`words` が配列）でも、学習進捗は初期化も変更もされない
- **イベントの流れ（自動リピートの回帰確認）**: Enter は keydown ごと、Space は keyup で、マウス・タッチは離したときに click が起きる、というブラウザの流れを再現した。そのうえで、表示中の語を途中で変えながら確認した。
  - Space を押し続け、語が変わってから自動リピートを起こして離しても、押し始めた語に1回だけ記録する
  - Enter の自動リピートでは回答せず（`preventDefault`）、別の語へ連続で回答しない
  - 離してから押し直せば、そのとき表示中の語に記録する（通常の再押下）
  - Enter / Space 以外のキーは押下情報を変えない
  - ポインターは押している間に語が変わっても押し始めた語に記録し、次の押下は新しい語に記録する

## ブラウザ確認（Playwright / Chromium、dev サーバー、speechSynthesis はスタブ）
390×844 と 320×568 で同じ確認をした。

1. **基本操作（停止中）**
   - 「わかる」を押すとその語に `known` が記録され、ボタンが選択状態になった。続けて「まだわからない」を押すと `unknown` と新しい日時に上書きされた。
   - ボタンを押しても次の語へは進まず、Attention の回数と「もう一度」の予約は0のままだった。
   - 次の語ではどちらのボタンも未選択で表示され、「前へ」で同じ語に戻ると前回の選択（✓ まだわからない）が表示された。
   - 再読み込みしたあとも記録は残っていた。
   - 英語の中心・画像の上端・ボタンの位置は、未回答・わかる・まだわからないで同じだった（390×844: 英語中心 170.3px、画像 251.5px。320×568: 159.3px、240.5px）。
2. **0.25秒/語で、表示の切り替えをまたいだ操作**: 押してから語が変わるまで押し続け、語が変わってから離した。マウス（わかる）、タッチ（まだわからない）、キーボードの Space（わかる）を5回ずつ、各サイズで計15回行った。
   - 15回すべてで、押し始めた語に正しい選択が記録された。離したときに表示されていた語には記録されなかった。
   - その間も自動周回は止まらず、Encounter は進み続けた。Attention は0のままだった。
   - 確認中に、タッチで押すと、直前にマウスやキーボードで押した別のボタンのフォーカスが外れたときの処理で、押し始めの語が消える不具合が見つかった。表示中の語に記録されてしまうため、フォーカスが外れても押し始めの語を消さないように修正し、修正後に上記の結果を確認した。
3. **未回答のまま遠征**: 0.25秒/語で105 Encounter まで進め、約26.5秒で遠征完了画面になった。localStorage のキーは従来の3つのままで、自己申告のキーは作られなかった。
4. **ダーク・reduced-motion**: ダーク / ライトの両方で reduced-motion を有効にし、回答、カードタップ（again の予約と「もう一度出します」の表示）、前回の選択の表示を確認した。横スクロールはなかった。
5. **既存データ・不正なデータ**: 学習履歴・設定（2秒/語、音声 OFF、補助文 OFF）・XP 900・Gold 50 と、壊れた自己申告データを入れて起動した。
   - 起動しても既存の3つのキーは変化せず、Level・XP・Gold・設定はそのまま表示された。
   - 回答すると自己申告のキーだけが新しい内容になり、学習履歴は変化しなかった。
6. コンソールエラーはなかった。

7. **キーの自動リピート（修正の確認）**: 0.25秒/語の自動周回中に理解度ボタンへフォーカスし、Space / Enter を押したままにした。語が変わるたびに自動リピートの keydown（`repeat: true`）を起こし、3回切り替わってから離した。
   - **修正前（d269723）**（390×844）: Space は4回すべて、離したときの語に記録された。Enter は1回の長押しで click が7回起き、4つの語に回答が保存された。
   - **修正後**（390×844・320×568）: Space・Enter とも4回すべて、押し始めた語に1回だけ記録された（click も1回）。
   - 同時に確認した通常の Space の短押し、マウス、タッチ（各4回）も、すべて押し始めた語に記録された。自動周回は止まらず、Attention は0のままだった。
   - 修正後に、1〜6 の確認（基本操作、各操作で15回、未回答で105 Encounter 完了、ダーク / reduced-motion）も両サイズでもう一度行い、同じ結果だった。

## 残課題
- 自己申告はまだ出現頻度・比率に反映していない（次のタスクで検討する）。
- 回答の取り消し（未回答に戻す）はできない。同じボタンをもう一度押すと、選択は変わらず日時だけが更新される。
- iPhone 実機（Safari、実際のタッチ操作）では確認していない。タッチは Chromium のタッチイベントで確認した。
- 理解度ボタンの行が増えた分、操作部が下にずれた。320px 幅ではページの高さが約58px増えた（320×568 で 699px → 757px）。390×844 はスクロールなしのまま。
- 「わかる」「まだわからない」の操作は、開発用表示や遠征完了画面には集計していない。
