# Task 016: 自己申告に基づく出題間隔への切り替え v1

## 目的
word-loop を「わからない語を重点的に確認し、わかる語への接触を減らすフラッシュカード」にする。
今回の方針変更は、従来の仕様（familiar 約9割の選出、カードタップの Attention など）より優先する。

土台は PR #8 の最新状態（a6a15ae。Task 013〜015 を含む）。

## 仕様
- familiar を約9割出す方針（9:1 選出）は廃止した。既知語を繰り返し表示して105回を埋めない。
- 表示回数だけで理解したと判断しない。判断に使うのは「わかる」「まだわからない」の自己申告だけ。
- 理解度ボタンは任意。回答入力・正誤判定・学習の自動停止は追加していない。

### 1. 「わかる」の出題間隔（暫定値。`src/lib/understanding.ts` の定数）
| 連続した「わかる」 | 次回出題可能日時 |
| --- | --- |
| 1回目 | 回答日時の1日後 |
| 2回目 | 3日後 |
| 3回目 | 7日後 |
| 4回目 | 30日後 |
| 5回目以降 | 90日後 |

- 定数: `knownReviewIntervalDays = [1, 3, 7, 30, 90]`、`dayMilliseconds = 24時間`（暦日・タイムゾーンは考えず、24時間単位で数える）。
- 次回出題可能日時（`nextDueAt`）より前には、その語を自動選出しない。期日が来ても通知はしない。
- 同じ Encounter での連打では連続回数を増やさない。同じ Encounter で回答を訂正した場合は、最後の回答を採用する
  （「わかる → まだわからない → わかる」と押しても1回分）。
  - その Encounter で最初に回答する前の記録をメモリ上に覚えておき、同じ Encounter の回答は毎回その記録から計算し直す（`answerUnderstanding`）。
  - Encounter は「押し始めた時点に表示していた語と、その通し番号」で決める。押下中に語が切り替わっても、押し始めた語の Encounter に記録する。

### 2. 「まだわからない」
- 「わかる」の連続回数を0に戻す（期日なし）。
- 遠征中は、回答した Encounter のあと別の5 Encounter を挟んでから再登場させる（`shortTermReappearGap = 5`、暫定値）。
  再登場は既存の「↻ again」ラベルで表示する。
- 同じ語の再登場予約は1件まで。再登場前に「わかる」へ訂正したら予約を取り消す。
- 再登場しただけでは理解度を変えない。再登場時にも「まだわからない」と答えれば、再び予約する。
- 未消化の短期予約は次の遠征へ持ち越さない（遠征の終了時・開始時に破棄）。保存された unknown の語は、次の遠征の復習候補になる。
- 待ち時間を埋めるために期日前の known を出さない。

### 3. 未回答
- 未回答（記録のない語）を known にも unknown にもしない。出題候補には含める。
- 回答せずに通過した語は、同じ遠征中には再選出しない。次の遠征では再び候補になる。
- 未回答の語は、過去の表示回数（learning-progress の `encounterCount`）が少ない語を優先し、同条件の語は乱数で偏らないように選ぶ。

### 4. 出題順序（`src/lib/scheduler.ts` の `selectNextWord`）
1. 再登場の時期が来た「まだわからない」の短期予約（予約の古い順）
2. 復習候補: 期日が来た known、過去に unknown と回答され今回の遠征ではまだ表示していない語。
   待っている期間（known は期日から、unknown は最後の回答から）が長い語を優先。同じ長さなら乱数。
3. 未回答で、この遠征でまだ表示していない語（上記の順）

- 同じ語の連続表示は避ける（予約語が直前の語なら1つ後ろへずらす）。
- 一度表示した復習語・未回答語は、回答がなければその遠征では再選出しない。明示的な「まだわからない」の回答があった場合だけ、短期予約で再登場する。
- new / growth / familiar の分類（`wordSelector.ts`）は、ラベルと XP の表示用に残した。出題可否・順序・理解度の判断には使わない。

### 5. 遠征の終了
- 105 Encounter を上限として維持する。
- 今すぐ出せる候補がなければ、105 未満でも遠征を終了する（`completeExhaustedExpedition`、完了理由 `exhausted`）。
  完了画面に「今出せる語を出し終えました。」と表示する。
- まだ順番が来ていない短期予約だけが残っていても、同じ語や既知語を出して回数を埋めない。
- 開始時点で候補が0件なら空の遠征を作らず、拠点画面に「今の復習はありません。」と表示する。XP・Gold・完了遠征数は増やさない。
- 途中終了した遠征は、実際に表示した Encounter 分の報酬を確定する（XP は Encounter ごとの合計、Gold は下記の現行式）。

### 6. カードタップの整理
- カード全体をタップする Attention 操作（透明ボタン）を廃止した。
- 「タップでもう一度」と「◯◯ をもう一度出します」の表示を削除した。
- カードの操作は「わかる」「まだわからない」だけ。
- 過去の Attention 履歴（learning-progress の `attentionCount` / `lastAttentionAt` / `attentionDebt`）は削除していない。

### 7. UI・操作
- 英語・日本語・画像・補助文の表示と、行の高さ固定（Task 013）は維持した。
- 回答しても自動周回は止めず、次の語へ飛ばさない。
- Task 015 の押し始めの語への記録と、Space・Enter の自動リピート対策はそのまま（記録先に Encounter の通し番号を加えただけ）。
- 「タップでもう一度」の行を外したので、理解度ボタンが約1行分上に寄った。英語・画像の位置は変わらない。
- 拠点画面の説明を「1回の遠征は最大 105 語。今出せる語を出し終えると、そこで終わります。」に変更した。

## 保存の変更
- キー: `word-loop.understanding`（キー名は Task 015 と同じ）
- version: 1 → **2**
- 追加項目:
  - `knownStreak`: 連続した「わかる」の回数（unknown は 0）
  - `nextDueAt`: known の次回出題可能日時（ISO 8601）。unknown は `null`
  ```json
  {
    "version": 2,
    "words": {
      "apple": { "status": "known", "answeredAt": "2026-10-24T10:00:00.000Z", "knownStreak": 2, "nextDueAt": "2026-10-27T10:00:00.000Z" },
      "reluctant": { "status": "unknown", "answeredAt": "2026-10-24T10:00:05.000Z", "knownStreak": 0, "nextDueAt": null }
    }
  }
  ```
- 書き込むのは回答したときだけ（読み込みでは書き換えない）。短期予約・同じ Encounter の回答前の記録はメモリ上だけで、保存しない。
- **互換読み込み**（`parseUnderstanding`）:
  - version 1 の known（追加項目なし）は「わかる1回目」: `knownStreak: 1`、`nextDueAt` は既存の `answeredAt` の1日後。
  - version 1 の unknown は `knownStreak: 0`・`nextDueAt: null`（復習候補）。記録のない語は未回答。
  - `answeredAt` を現在時刻に書き換えない。期日は保存された `answeredAt` だけから計算するので、再読み込みのたびに先送りされない。
  - 不正な追加項目（負や小数の `knownStreak`、日時でない `nextDueAt` など）は `status` と `answeredAt` から補う。
    `status` / `answeredAt` 自体が不正な語の記録だけを捨て、履歴全体は初期化しない。
- ほかのキー（`word-loop.learning-progress` version 2、`word-loop.learning-state`、`word-loop.player-progress` version 1）は、キー・形式・version とも変更していない。
  学習履歴・設定・XP・Gold・Task 015 の回答は保持される。

## 報酬
- XP: Encounter ごとに familiar 1 / new 5 / growth 5 / again 10（変更なし）。途中終了でも、表示した Encounter 分だけになる。
- Gold: 遠征完了時に **基本 Gold（按分）** + (new + growth) × 2 + again × 5。語ごとの加算・XP・Level の係数は変更していない。
- **基本 Gold の按分（追加修正）**
  - 当初の実装では、基本100 Gold が Encounter 数に関係なく付いていた。1語の遠征でも 102 Gold になり、unknown が数語だけ残っていると、短い遠征を繰り返して Gold を得られた。
  - 修正後の基本 Gold = `Math.round(returnBaseGold × 実際の Encounter 数 / encounterLimit)`（`rewards.ts` の `calculateReturnBaseGold`）。
    - 値は既存の定数 `returnBaseGold`（100）と、遠征の上限（`ExpeditionState.encounterLimit` = `expeditionEncounterLimit` 105）を参照し、数値を重複させていない。
    - 遠征の集計（`ExpeditionResultCounts`）に `encounterCount` と `encounterLimit` を加えた。
  - 例: 0 Encounter → 0（基本 Gold・その他の報酬とも発生しない）、1語 → 1（new なら合計 1 + 2 = 3）、3語 → 3（new なら合計9）、105語 → 100（従来どおり）。
  - 上限を超える値は上限として扱う。0 Encounter の遠征は、もともと完了させない（`completeExhaustedExpedition`）。
  - 過去に獲得した Gold と保存データ（`word-loop.player-progress` version 1）は変更していない。今後の遠征の報酬が加算されるだけ。

## 残課題
- 短い遠征も完了遠征数を1つ増やす（今回は変更していない）。
- 「前へ」で戻った表示は新しい Encounter として数えるため、「わかる」→「前へ」→「わかる」で連続回数が2回分増える（同じ遠征の中で期日が延びる）。必要なら「同じ遠征では連続回数を1回だけ増やす」などに変更する。
- 回答を未回答に戻す操作はない。
- 期日は端末の時計で判断する。端末の時刻を変えると出題も変わる。
- 未回答の語は毎回の遠征で候補になるので、200語のうち未回答が多い間は、遠征の大半が未回答の語になる（未回答のまま通過した語を次の遠征で後回しにする仕組みは表示回数の優先だけ）。
- 完了画面の内訳（familiar / new / growth / again）は従来のまま。known / unknown の集計や、次の復習日の表示はない（新しい統計画面は今回の対象外）。
- XP の種別（new 5 / familiar 1）は表示回数による分類のまま。Attention を廃止したので、growth は過去の debt が残っている語だけになる。
- `wordSelector.ts` の 9:1 選出、`recall.ts` と App の Recall 処理は使われずに残っている。今後も使わないと決まったら整理する。
- iPhone 実機（Safari、実際のタッチ操作）では確認していない。
